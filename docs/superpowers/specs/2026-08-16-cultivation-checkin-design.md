# 修仙打卡器 · 设计规格说明

- 日期：2026-08-16
- 主题：修仙戒律打卡器（Calendar Check-in）
- 状态：已获用户批准

## 1. 目标与定位

一个「修仙戒律」主题的日历打卡器，帮助用户每日打卡并记录修为。核心玩法：

- **绿色 = 今日修为 +1**（守戒成功）
- **红色 = 破戒！！！**（破戒标记）

以可爱画风呈现，轻量、免费、零后端，全部托管在 GitHub。

## 2. 功能需求

### 2.1 打卡时间窗口
- **今日**：只能在 `23:00 ≤ t < 23:30`（半开区间，用户本地时区）打卡。
- **过去日期**：任意时间可补卡，红/绿任选。
- **未来日期**：锁定，不可打卡。
- 时间窗口外，今日按钮禁用并显示倒计时（窗口前倒计时至今天 23:00；窗口后倒计时至次日 23:00）。
- 今日在窗口内重复打卡时，覆盖更新当次记录（颜色/备注），同一日期仅保留一条记录。

### 2.2 打卡颜色
- 用户每次打卡自选绿色或红色。
- 绿色 = 今日修为 +1；红色 = 破戒标记。

### 2.3 记录功能
- 每个日期保存一条记录：颜色 + 文字备注。
- 点开日期可查看、新增、编辑、删除记录。

### 2.4 提醒机制（双通道）
- **页面开启时**：23:00（用户本地时区）弹可爱弹窗 + 浏览器通知（需授权）。
- **浏览器关闭时**：GitHub Actions 定时任务在 `15:00 UTC`（= 北京时间 23:00）触发，通过 Server酱 推送到微信。推送密钥存为仓库 Secret：`SERVERCHAN_SENDKEY`。
- 推送文案（示例）：`⏰ 修仙打卡提醒：今日修为等你来 +1！23:00–23:30 记得打卡，别破戒啦~`。推送失败仅记录日志，不让 workflow 报错失败。

### 2.5 统计面板
- 修为值（绿色累计次数）
- 连续修炼天数：从「今天」向前连续统计绿色天数；若今天尚未打卡，则从「昨天」向前统计；一旦遇到非绿色（红色或未打卡）即中断。今天若为红色，连续天数为 0。
- 破戒次数（红色累计次数）
- 以上统计均实时从 `records` 派生计算，不单独存储。

### 2.6 部署
- 独立 GitHub 仓库，启用 GitHub Pages，部署于 `https://clauderead.github.io/<repo>/`。
- 不影响现有博客（用户名站点）。
- 子路径部署要求：资源使用相对路径，`manifest.webmanifest` 的 `start_url`/`scope` 与 Service Worker 的 `scope` 需适配 `/repo/` 子路径。

## 3. 技术架构

纯静态 PWA，无构建步骤，无后端。

| 部分 | 技术 | 职责 |
|---|---|---|
| 前端页面 | 原生 HTML/CSS/JS | 日历、打卡、记录、统计 |
| 本地数据 | `localStorage` | 打卡记录（不跨设备同步） |
| PWA | manifest + Service Worker | 可安装、离线、浏览器通知 |
| 定时推送 | GitHub Actions + Server酱 | 关浏览器时的微信提醒 |

### 3.1 仓库结构
```
calendar-checkin/
├── index.html
├── style.css
├── app.js            # 日历 + 打卡 + 时间窗口 + 统计
├── reminder.js       # 页面内可爱弹窗 + 倒计时
├── sw.js             # 离线缓存 + 通知
├── manifest.webmanifest
├── icons/            # PWA 图标：192×192、512×512 PNG + maskable
├── .github/workflows/remind.yml
└── README.md
```

### 3.2 数据模型
```json
{
  "2026-08-16": { "color": "green", "note": "今日打坐 1 小时" },
  "2026-08-15": { "color": "red",  "note": "熬夜破戒" }
}
```
- 键：`YYYY-MM-DD`（本地时区）。
- 存储在 `localStorage`，键名如 `cultivation-records-v1`。

## 4. 关键约束与已知限制

1. **微信推送是纯提醒**：记录存于浏览器本地，GitHub Actions 无法读取「今日是否已打卡」，故推送不判断已打卡状态（用户已打卡则忽略即可）。
2. **GitHub Actions 定时精度与时区**：免费仓库的 scheduled workflow 可能有数分钟到更长的延迟，且按 UTC 配置。推送固定按北京时间 23:00（15:00 UTC）触发；页面内弹窗则按用户本地时区。二者在非 UTC+8 时区下可能不一致，本设计以 UTC+8 为准。
3. **数据不跨设备**：记录仅在当前浏览器本地。
4. **通知授权**：浏览器通知需用户首次授权；PWA 安装后体验最佳。

## 5. 视觉方向

「修仙小灵宠」可爱画风：

- 主形象：打坐的圆滚滚熊猫灵宠 🐼，弹窗中「说话」。
- 配色：奶白/米黄底 + 青绿（修为）+ 朱红/粉红（破戒）+ 淡紫点缀。
- 字体：圆润中文字体 + 圆体英文。
- 质感：大圆角、柔和阴影、漂浮动画、云朵/仙气元素。

## 6. 验收标准

1. 今日仅 23:00–23:30 可打卡，其余时间按钮禁用并显示倒计时。
2. 过去日期任意时间可补卡（红/绿任选）。
3. 未来日期锁定。
4. 每个日期可保存颜色 + 文字备注，并可编辑/删除。
5. 统计面板正确显示修为值、连续天数、破戒次数。
6. 页面开启时 23:00 触发可爱弹窗 + 浏览器通知。
7. GitHub Actions 定时任务按 UTC 配置正确，可调用 Server酱 推送。
8. 项目可在 GitHub Pages 子路径部署且不影响博客。
9. PWA 可安装、有图标、可离线访问。
